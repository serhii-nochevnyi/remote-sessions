# ADR-13 — Local desktop creation and terminal ergonomics

- **Status:** accepted
- **Date:** 2026-11-21
- **Decision owner:** user; explicitly accepted recommended SQLite ADR-13 on 2026-11-21
- **Scope:** Wave 1 local Mac workflow, planned as vertical MVP slices
- **Supersedes:** none; preserves ADR-12 Rust selection and original Session/Runtime/View boundaries
- **Related:** INV-001-local-desktop-workflow; docs/planning/ARCHITECTURE.md; docs/planning/UI-SPEC.md
- **UI design:** docs/planning/UI-SPEC.md, desktop tabs and create dialog; expanded terminal and explicit zoom additions below

## Context

The baseline at 91d9695 supports independent tmux runtimes and native desktop tabs/output/input/reconnect. Creation still requires a development CLI. The native client cannot select a workspace or create/resize a session, terminal font shrinks to fit, and geometry changes participate in attachment identity. Four verified research lines retained in the local planning record found that lost create replies can produce duplicate launches without durable operation identity. SQLite transactions cannot include tmux side effects, so recovery must explicitly preserve uncertainty. Background provider startup, same-attachment redraw ordering and output-pressure behavior require empirical acceptance.

## Decision

- Use a host-owned, versioned SQLite catalog for workspaces, session metadata, runtime attempts and create operations. Keep it under private per-user application state on the internal Mac volume; source and project folders may remain on KINGSTON. Select and verify explicit journal/sync settings during implementation. Do not silently reset unreadable, corrupt or newer-schema stores; report an actionable error while preserving existing tmux runtimes.
- Bind each create operation to one stable request key, normalized workspace/profile inputs, reserved session/runtime IDs and resolved launch identity. Persist the native pending request before first submission and host reservation before any external effect; durably mark the may-have-launched boundary before issuing tmux spawn. Equal retries return/query the same operation, conflicting payload reuse is rejected, and outcomes or tombstones remain retained for every accepted key. An unresolved attempt never receives an automatically generated replacement key.
- Reconcile a may-have-launched operation against its precise reserved managed tmux identity. A matching live or retained exited pane can finalize the original result. Missing/unreachable/replaced tmux, a subprocess timeout or insufficient identity evidence yields a visible unknown state and no automatic respawn. Retry only status/reconciliation unless there is affirmative evidence no spawn was possible. The UI offers refresh/reconnect for unknown outcomes; a distinct new launch requires an explicit separate user action explaining that the earlier outcome remains unknown.
- Preserve discoverability and original IDs of existing managed P0 tmux sessions. Mark legacy provenance and unknown workspace/operation metadata rather than fabricating history. Closing a view, restoring preferences, upgrading metadata or restarting the agent must not stop or recreate a surviving runtime.
- Add a macOS purpose-specific Rust folder-picker command using Tauri's native dialog and host registration. Return an opaque workspace ID and display metadata to the WebView. Canonicalize an existing directory, retain identity evidence and revalidate identity/access immediately before launch; changed/deleted/replaced directories require reselection. Resolve symlinks at selection and reject changed targets. Reject unsupported non-UTF-8 launch paths visibly. Test internal paths and accessible KINGSTON paths from the actual background services; picker success is not proof of host access.
- Expose product creation using only a registered workspace ID and the closed Claude Code/Codex profile enum. Resolve executable and required PATH/interpreter environment at the host, with explicit readiness diagnostics. Preserve provider authentication, trust, approval and sandbox defaults. Never accept WebView executable paths, arbitrary arguments, shell strings or environment overrides. Keep legacy arbitrary-argv development probes separate and unavailable through native product commands.
- Submit create through a typed UI/native/host operation with cancel, pending, definite failure, unknown, launched and exited states. Open/select a successful runtime once by stable ID, deduplicating inventory/result races. Distinguish pane creation from provider readiness or early exit. A canceled picker/draft before submission launches nothing; canceling a view after submission cannot undo an uncertain external effect.
- Keep tmux manual window sizing and require the live host ownership lease for runtime resize. Serialize runtime/pane identity, token validity and sequence checks with controller transitions at the mutation boundary. Reject spectators, expired/stale tokens, wrong runtimes, invalid geometry and reordered work. Coalesce at most one in-flight resize plus the newest pending proposal per view; preserve the baseline 2–500 columns and 2–200 rows bounds.
- Converge the authoritative tmux pane size, native attachment PTY size and xterm grid without recreating the attachment on presentation changes. Return measured dimensions and a size revision scoped to runtime/connection epoch. Discard late replies from replaced views/owners and remove layout dimensions from React connection identity. A timeout requires readback/ordering recovery before later mutations; genuine reconnect uses a fresh view and redraw with no input replay. Spectators follow the authoritative grid while zooming/panning locally without changing runtime size.
- Provide explicit terminal zoom/reset, expanded-content layout and a separate native fullscreen control. Start with 14 px default and bounded 10–28 px font, Cmd +/−/0 shortcuts, visible keyboard focus and an obvious way out of expanded mode. Persist validated font/tab order/active selection/expanded preference as per-device presentation state, separately from host-authoritative data. Do not restore OS fullscreen automatically, persist transient leases or erase preferences after a temporary inventory failure. Confirm shortcuts, focus and fit in native acceptance.
- Preserve bounded terminal queues and isolate stalled viewers with disposal and fresh-redraw recovery. Add deterministic coverage for flood/slow observer, query-generated replies, focus and color updates, short and multi-chunk Unicode/multiline paste, and ambiguous delivery with no replay. Supported startup/editing flows for both providers and healthy-view/runtime progress are W1 acceptance gates; complete streamed-response/approval compatibility remains later reliability work.
- Deliver through ordered vertical slices with each slice's UI/native/host contract and failure checks together. Use GitHub Issues linked to the wave milestone, isolated branches and reviewed PRs. Keep canonical Shipyard planning and receipts local; publish readable roadmap/design/acceptance documents in the repository. No automatic merge authorization is established by this ADR. Require core/native CI and logged-in real Mac acceptance with both providers, source/tool versions, dimensions, identity continuity and zero model prompts; write W1 evidence separately from historical P0 reports.

## Consequences

- SQLite adds dependency and schema work but avoids a custom replay/compaction implementation. A journal-only approach was evaluated and remains an alternative if the user chooses its maintenance trade-off.
- An uncertain launch may remain visible and require a deliberate user decision. This is the cost of avoiding duplicate execution when absence cannot prove that no previous spawn occurred.
- Host state on internal storage avoids making a removable source volume the operation ledger. This does not assert power-loss, filesystem-corruption or unplug guarantees beyond explicitly exercised checks.
- Creation, resize and preferences share source files and must be sequenced or factored with clear ownership. No speculative parallel edits to the same native/host boundaries.
- R1–R7 in the investigation risk register remain blocking implementation acceptance checks: crash reconciliation, storage faults/compatibility, service folder/provider access, live redraw/ownership races, slow-view isolation, terminal protocol/paste, and native evidence. A failed proof revises the affected design before the slice is accepted. Research does not count as passing those tests.
- The proposed defaults for font and shortcuts are adjustable after native usability testing without changing the authority/lifecycle architecture.

## Out of scope

- Remote runtime access, relay, OIDC/enrollment, pairing and E2EE implementation; those remain separate waves and gates.
- iPhone implementation in W1; physical-device feasibility remains early W2 and the product target remains Mac + iPhone.
- Production installer, signed distribution, automatic service setup, generalized session history/rename/stop UX and complete provider-task compatibility; W3 and later waves own them.
- Arbitrary shell profiles, split panes, structured chat/approval cards, terminal recording, automated provider tasks and provider approval-policy changes.
- Claiming Gate 1 acceptance, Gate 2 decomposition or tested implementation before their actual results exist.
