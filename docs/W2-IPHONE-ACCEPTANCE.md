# Signed iPhone terminal feasibility

Run the bundled Tauri and xterm fixture on a signed physical iPhone. The fixture records synthetic terminal input locally and has no host, provider, relay or remote runtime access. Use the [shipped matrix](../apps/client/w2-fixture/cases.json) for actions and independent expected bytes. Record observed results in [the evidence report](W2-IPHONE-EVIDENCE.json). Keep signing material, device identifiers, personal clipboard data and generated artifacts out of Git. Use redacted references to retain the build log, installation result and observations for review.

## Repository CI

The [scaffold workflow](../.github/workflows/ci.yml) runs Linux `core` with `make check` and macOS `native` with `make check-native` on push and pull request. Both jobs use Rust 1.97.1 and locked npm dependencies. Run them through the repository delivery gate even while device setup is on hold. For physical acceptance, record the passing job links and checked revision for the signed candidate in the cohort's `ci` record. The operator can start the scoped preflight while CI is running.

## Pre-Xcode gate

From the worktree root, check Node 24, npm 11 and Python 3.11 or newer, then use `npm ci` with the root lockfile. Keep the same Bash shell for the Rust setup, scoped Mac Cargo check, iOS target installation and signed packaging. Initialize the worktree's Rust homes and select Rustup.

```bash
export RUSTUP_HOME="$PWD/.cache/rustup" CARGO_HOME="$PWD/.cache/cargo"
mkdir -p "$RUSTUP_HOME" "$CARGO_HOME"
export PATH="$CARGO_HOME/bin:$PATH"
if ! W2_RUSTUP=$(type -P rustup); then
  w2_git=$(git rev-parse --path-format=absolute --git-common-dir) || exit 1
  W2_RUSTUP="${w2_git%/*}/.cache/cargo/bin/rustup"
fi
test -x "$W2_RUSTUP" || exit 1
export W2_RUSTUP
```

For an empty worktree cache, run `"$W2_RUSTUP" toolchain install 1.97.1 --profile minimal --component rustfmt --component clippy`. If the pin exists without those components, use `"$W2_RUSTUP" component add --toolchain 1.97.1 rustfmt clippy`. Probe the pinned `cargo -V`, `rustc -V`, `rustfmt --version` and `cargo clippy --version` with `"$W2_RUSTUP" run 1.97.1`. Resolve the pinned binaries for child processes and confirm bare `cargo` and `rustc` pick up 1.97.1.

```bash
w2_cargo=$("$W2_RUSTUP" which --toolchain 1.97.1 cargo) || exit 1
export PATH="${w2_cargo%/*}:$PATH"
cargo -V
rustc -V
```

With that environment, run each of the four checks separately at the repository root. Retain output, exit status, failed runs and reruns against the revision selected for signing.

```bash
bash -ec 'check_rule() { local path=$1 expected=$2 rule tab; rule=$(git check-ignore -v --no-index -- "$path"); tab=$(printf "\t"); [[ "$rule" == .gitignore:*":$expected$tab$path" ]]; }; fixture=apps/client/w2-fixture/src-tauri; check_rule "$fixture/gen/apple/project.pbxproj" "/$fixture/gen/"; check_rule "$fixture/permissions/autogenerated/w2_begin_attempt.toml" "/$fixture/permissions/autogenerated/"; for source in "$fixture/src/lib.rs" "$fixture/capabilities/w2-fixture.json"; do result=0; git check-ignore -q --no-index -- "$source" || result=$?; test "$result" -eq 1; done'
node node_modules/vite/bin/vite.js build apps/client/w2-fixture --config apps/client/w2-fixture/vite.config.ts
bash -ec 'out=$(node --test --test-reporter=tap --test-name-pattern="^declared fixture boundary (matches the iOS-only contract|rejects broadened declarations)$" apps/client/w2-fixture/fixture.test.ts); printf "%s\n" "$out"; printf "%s\n" "$out" | grep -Eq "^ok [0-9]+ - declared fixture boundary matches the iOS-only contract$"; printf "%s\n" "$out" | grep -Eq "^ok [0-9]+ - declared fixture boundary rejects broadened declarations$"; printf "%s\n" "$out" | grep -Eq "^# pass 2$"'
"$W2_RUSTUP" run 1.97.1 cargo check --locked -p remote-sessions-client
```

The ignore guard requires the exact generated-path rules and checks source visibility independently of Git's index. In a disposable Git repository with a copy of the root ignore file, the guard should fail with either generated rule replaced by a blanket `/apps/client/w2-fixture/src-tauri/` rule. It should also fail if that blanket rule is added alongside the two exact rules because source visibility changes.

Run this gate regardless of device and signing availability. Require all four checks before the operator probes or invokes Xcode for packaging. If a check or prerequisite is unavailable, record the reason and hold packaging. Rerun the gate when the signing checkout changes. The live Mac invoke regression follows signed packaging.

## Signed-device procedure

### 1. Build and verify the generated launcher

In the preflight shell, install and confirm the physical iOS target.

```bash
"$W2_RUSTUP" target add --toolchain 1.97.1 aarch64-apple-ios
"$W2_RUSTUP" target list --toolchain 1.97.1 --installed
xcode-select -p
xcodebuild -version
xcrun --sdk iphoneos --show-sdk-version
xcrun --sdk iphoneos --show-sdk-build-version
xcrun --find devicectl
xcrun --find simctl
```

Use full Xcode and record its complete version and build, the selected iPhoneOS SDK version and build, and device and simulator tooling availability. Check CocoaPods if the generated project needs it. With the authorized operator and registered physical device available, record the full Git revision and confirm the complete fixture source and lockfiles match that revision. Use a fresh target directory or a clean iOS Release build so that the build log identifies the fixture Cargo manifest and its output unambiguously.

```bash
cd apps/client/w2-fixture
node ../../../node_modules/@tauri-apps/cli/tauri.js ios init --skip-targets-install
node ../../../node_modules/@tauri-apps/cli/tauri.js ios build --target aarch64
```

Capture the CLI commands, exit statuses and full output in a retained redacted log. Require the locked CLI's generated `start_app` validation and successful linking of the generated iOS launcher. From that log identify the fixture Rust archive actually linked by the Release `iphoneos` launcher, then run `xcrun nm -arch arm64 -gU "$w2_archive"`. Verify a defined global `_start_app`, the Tauri export through which the launcher reaches the registry-bearing Rust `run` function. Retain the archive and symbol inspection reference alongside the build-log SHA-256. Hold physical installation until the entry validation is bound to the exact signed app selected in step 2.

### 2. Bind the signed build to the phone and generated settings

Read the physical iPhone model and iOS version/build from **Settings > General > About** and confirm the selected installation destination. Give the phone a locally chosen redacted alias. Use `xcodebuild -list -json` from the generated project directory to identify the app scheme and project or workspace. Run `xcodebuild -showBuildSettings -json` there for that scheme in Release with the `iphoneos` SDK. Select the app target's `IPHONEOS_DEPLOYMENT_TARGET` and `SDKROOT`. Compare the deployment target with `MinimumOSVersion` from the built app's Info.plist and compare SDKROOT with `xcrun --sdk iphoneos --show-sdk-path`. Record the matching generated settings. An installation on this tuple requires the generated deployment target to be at or below the phone's OS version.

Sign through Xcode or an authorized registered-device path, then run `codesign --verify --deep --strict "$w2_app"` on the selected app. With the verified app, retain a single archived copy of the signed bundle and record its SHA-256 as the bundle fingerprint. For example, use `ditto -c -k --keepParent "$w2_app" "$w2_signed_archive"` followed by `shasum -a 256 "$w2_signed_archive"`. Bind this fingerprint to the inspected revision, retained build-log digest, linked archive check and generated settings before installation. Use the same app from the verified archive for installation, verify its signature after extraction, and retain the record linking the install input to the observed bundle identifier, version and build on the phone. Use an install operation that takes the already built app. If anything rebuilds or re-signs the app, repeat the pre-install checks and binding with the new artifact.

Record SHA-256 for the exact `cases.json`, root `package-lock.json` and `Cargo.lock`, and standalone fixture `src-tauri/Cargo.lock`. Record the installed Node, npm and locked Vite, Tauri CLI, Tauri, wry and xterm.js versions together with the full Cargo and rustc version output. Keep the recorded keyboard languages/settings and starting orientation fixed. Changed settings, device, fixture, source or bundle require a new cohort. An incomplete or conflicting tuple holds acceptance.

### 3. Verify the effective boundary and offline startup

Use the `capabilities.json` and `acl-manifests.json` in the signed iOS fixture build's Cargo `OUT_DIR`. Confirm that the file-based `capabilities.json` has no additional definitions. Read the effective signed-build config for the sole inline `w2-fixture` capability, restricted to iOS, the local origin and the single `w2-fixture` window. Resolve each allow grant through `__app-acl__` in `acl-manifests.json`. Confirm only these recorder handlers and permissions are present.

| Allow grant | Resolved command |
| --- | --- |
| `allow-w2-begin-attempt` | `w2_begin_attempt` |
| `allow-w2-append-input` | `w2_append_input` |
| `allow-w2-read-attempt` | `w2_read_attempt` |

Look for extra capabilities, origins, commands, desktop handlers and deny or allow rules that change this mapping. Record the effective config and generated artifact digests, tying them to the signed build log and bundle fingerprint. Inspect the signed Info.plist and entitlements for unexpected network or URL access. From the repository root inspect the iOS Cargo tree for host, provider and desktop bridge dependencies.

```bash
"$W2_RUSTUP" run 1.97.1 cargo tree --locked --manifest-path apps/client/w2-fixture/src-tauri/Cargo.toml --target aarch64-apple-ios
```

Launch the installed app in airplane mode with Wi-Fi and cellular off. Observe the bundled fixture screen. Start an untouched generation and use **Read** before giving any input to verify zero startup bytes. Start a fresh Ukrainian typing attempt, enter `ї` and Return, then use **Read**. Record the tracer's begin, append and read operations and the exact `d1970d` snapshot from the installed app.

After signing, launch the checked-out Mac app against a private local lab with empty or synthetic inventory. For a fresh disposable lab, run `make build-runtime`, `npm run tauri -- build --debug --bundles app`, then `python3 scripts/desktop_lab.py up` and `python3 scripts/desktop_lab.py run`. The default lab starts a synthetic Python probe. Use the native development WebView inspector to exercise the app's existing IPC.

```js
await window.__TAURI_INTERNALS__.invoke("scaffold_status")
await window.__TAURI_INTERNALS__.invoke("local_inventory")
```

Verify the scaffold stage advertises zero capabilities and the inventory contains only the expected synthetic probe or is empty for an empty lab. Inspect the Mac registry in [the desktop native entry](../apps/client/src-tauri/src/lib.rs) and verify it excludes the three fixture commands. Record the result against the signed build reference. If this check created a disposable lab, close the app and run `python3 scripts/desktop_lab.py down`. The scoped Mac compile check precedes packaging and the live invoke regression assesses the running desktop app. W1 real-provider acceptance is a separate gate.

### 4. Qualify and measure composition

Use the signed offline fixture with the recorded stock software keyboards. Record language, autocorrection, predictive input, external keyboard state and any other settings relevant to the gesture. In separate qualification runs on each signed cohort, find or retest the exact taps or keys for each manifest recipe. Rehearse each recipe twice with observable preedit and end action, regardless of recorder output. Record the cohort fingerprint, rehearsal IDs and what the operator saw. Freeze the recipe on the baseline and reuse the same procedure for any correction or comparison.

| Case | Visible preedit | End action | Final native hex |
| --- | --- | --- | --- |
| Composition commit | `é` | Commit once without Return | `c3a9` |
| Composition replacement | `é`, then `è` while still composing | Commit `è` once | `c3a8` |
| Composition cancel | `é` | Cancel without submitting | empty |

For each measured run, start the case and execute the qualified preedit steps. Keep the xterm textarea focused until the automatic **Active native checkpoint** appears while preedit is still visibly active. Capture the latest completed checkpoint before the end gesture, including its event sequence, case, attempt, generation, accepted-event count and bytes. For replacement, capture it after the visible replacement and before commit. The trace must show at least two nonempty `update` events by that checkpoint. After the end action, use **Read** once and capture the separate final native snapshot and the complete **Attempt event trace**. Preserve every trace event through the final read, including all rejected or admitted `onData`, append dispatches and acknowledgments. The fixture exports text-free events with sequence and relative timing. Read `nextSequence` for each snapshot from its matching trace event's `nativeSequence` and keep the snapshot's visible bytes and accepted-event count separately. For composition, use the in-preedit readback and ordered trace to establish `start_empty`.

A clean commit or replacement has zero accepted input throughout preedit, one admission after `compositionend`, one matching dispatch and acknowledgment, and one independent final segment. Cancellation has an end event, no admitted input or appends, and an empty final snapshot. Preserve a known native acceptance before `compositionend` as a failure, including an acceptance between the last empty sample and the end event. A rejected premature callback, missing or unfocused checkpoint, uncertain order, incomplete trace or missing repeatable gesture keeps the attempt inconclusive. Preserve wrong recorder output and duplicated appends after a qualified gesture with established order. Run two distinct clean attempts per frozen recipe.

### 5. Measure WKWebView and complete the matrix

Run the remaining actions in the case manifest on the same signed bundle and physical tuple. Capture each visual outcome and native result under the same attempt reference.

- Give each app launch a redacted label, and give each measured run a separate report ID. For ordinary cases, check the empty native snapshot after **Start**, then refocus and perform the ordered actions. Capture the final **Read** first. If the visible result lacks the native attempt ID and generation, use a separate background and return after the final capture to read the **Interrupted attempt** identifiers and cross-check its retained hex and count. In recovery cases, capture the interrupted identifiers from the measured transition and verify the fresh generation separately after the final read. Hold a run if its native identities cannot be established.
- For English and Ukrainian typing, record cursor visibility and the exact typed bytes and Return.
- For both Unicode paste samples, use **Paste sample** and the iPhone's visible **Paste** action in separate fresh runs. Use only the exact synthetic sample as the clipboard input. Record focus, Paste availability and native output. The multiline vector has one carriage return at each line break. Run each route twice cleanly for both samples.
- Long-press the fixed `COPY-Ї` token, adjust selection handles, copy it and verify the exact token in a separate text field. Read the fixture snapshot for unexpected input. In the scroll case, swipe into the history and back to the prompt and cursor, then read the snapshot.
- Measure the prompt, cursor, viewport dimensions, focus and visibility before and after opening the keyboard. Record the same observations at portrait, landscape and restored portrait for rotation. Check that the prompt and cursor stay visible and that the action adds no input bytes.
- For app switch and lock/unlock, use separate cases. Read the initial snapshot before leaving the fixture. On return capture the retained old generation and compare its bytes and accepted events with the initial snapshot. Deliberately choose **Start fresh and refocus** before fresh input. Record the new generation, prompt visibility, fresh bytes and whether the old generation delivered an extra event. A retained snapshot flagged as uncertain keeps that run inconclusive.
- Capture ordered **Viewport and focus events** for WKWebView cases where available. Record an unavailable signal and its reason when the signed device still provides the required visible observation and native result. Composition ordering always requires the full separate composition trace.

Run two clean, consistent attempts per mandatory case and paste route. Preserve previous failures and uncertain results in chronological order. After an inconsistent result, record two fresh clean runs for that case, including both routes for a paste case. Store accepted event lengths and timing where available. Exact native bytes, single delivery and no replay are required.

## Shell disposition and acceptance

- A complete physical pass supports `continue-tauri-evaluation` for that tuple. Link the last two clean support attempts per mandatory case or paste route. Record `production_shell` and `minimum_ios` as `open` pending evidence and generated-settings review.
- A tooling or evidence hold uses `inconclusive`. Record the failed prerequisite, missing observation or ambiguous result and retain any partial measured records.
- An established mandatory failure uses `mandatory-failure`. Keep the original attempt, reproduce the same failure on the signed baseline under the same conditions, and attribute it to the responsible layer. Preserve the failed records and name their IDs under `correction.baseline_attempt_ids`. In `correction` record the `case_id`, `layer`, exact file `scope` and one narrow `change`. If a correction needs files outside the evidence change, return the attributed failure and file scope to the coordinator for a dedicated corrective ticket.
- Run the signed corrected build under the same physical conditions and keep both revisions and sets of observations. Only an unresolved same-case failure before and after the correction supports `comparison-eligible`. Link both baseline failures and the corrected failure. A signed alternate shell must reuse the fixture matrix and digest, expected bytes, operator actions, qualified recipes and same physical conditions. Keep its own bundle, launcher proof and equivalent effective local boundary evidence. Link its measured attempts, attribute the result to the observed layer in `decision.rationale` and use `review-comparison` after a complete alternate-shell matrix. The unresolved Tauri failure keeps physical acceptance open in this disposition.

Review the passing CI links, generated settings, signed build provenance and physical evidence before closing W2. After that review, run the signed acceptance command. It returns success only for a complete passing physical report.

```bash
python3 tests/integration/w2_iphone_evidence.py --manifest apps/client/w2-fixture/cases.json --report docs/W2-IPHONE-EVIDENCE.json --require-pass
```

Send the reviewed result or hold to the coordinator for state synchronization. A hold or failure keeps the human merge checkpoint and W2 acceptance pending.
